# Demo Page UX Spec

<!-- TODO0 consider deleting this spec once the work below is implemented and released. -->

This spec covers a UX pass over the four WASM demo pages (Clock, Armatron, Ballet, Skeleton
Clock) and the gallery page. It is written to be implemented without further conversation
context. Verify every "verify:" note against the code before relying on it.

## Background: how the pages are built

- The gallery page is generated by `xtask/src/main.rs` (`DEMOS_INDEX_TEMPLATE` plus
  `DemoRecord::demo_card_html`). It is regenerated on every `just build-pages`, so gallery
  changes need only an xtask edit.
- Each demo's live page source is `crates/<crate>/www/` (see `pages/demos.tsv` for the
  slug → crate mapping). Armatron keeps its CSS in `www/styles.css`; the other three demos
  inline their CSS in `www/index.html`.
- **Frozen snapshots**: `just bump-demo-version <slug>` copies the live `www/` into an
  immutable `pages/demos/<slug>/vN/` directory. `just build-pages` copies those snapshots
  into `target/pages/` and rebuilds only the WASM `pkg/` fresh from the crate. Therefore
  edits to `crates/*/www` are invisible in the gallery until a version bump.
- `just run-all-wasm` builds and serves the gallery at `http://localhost:8090/`.

## Scope decisions (already made — do not re-litigate)

- Change only the live `www/` sources, the xtask gallery template, and (as the final step)
  bump each demo to a new frozen version. Do **not** edit existing `pages/demos/*/v1` or
  `v2` snapshots.
- The description/instructions UI is an "index card on the desk" (design below).
- Phone strategy is scale-to-fit everywhere plus an explicit fullscreen "device mode".
- External links: repo `https://github.com/CarlKCarlK/linkage-blaze`, author page
  `https://medium.com/@carlmkadie`.

## Feature 1: Back-to-gallery link on every demo page

Every demo page gets a small, always-visible link back to the gallery.

- Placement: top-left corner, fixed position, above the desk scene.
- Style: fits the desk aesthetic — a small paper tag / label chip (warm off-white paper
  `rgb(247, 241, 230)` /* warm paper white */, thin border, slight drop shadow, small
  rotation of about -2deg is welcome), reading `← Gallery`.
- URL: demo pages are served at `/demos/<slug>/vN/`, the gallery at `/demos/`, so the
  relative href is `../../`. Verify this resolves correctly under `just run-all-wasm`.
- Must remain visible and tappable on phones (minimum 44 px touch target) and must be
  hidden in device mode (Feature 4).

## Feature 2: The index card (description + instructions + links)

A paper index card lies on the desk beside the device — like a museum spec card.

### Behavior

- Resting state: a small card (roughly 180×120 px on desktop, scaled with the scene),
  rotated ~3°, positioned on the desk where it does not cover the device screen. It shows
  the demo title and the first line of the description, visually truncated.
- Click/tap: the card animates up to a centered, readable size (max-width ~34rem, max
  ~90vw / 85dvh with internal scroll if needed), the desk behind dims slightly
  (`rgba(0, 0, 0, 0.35)` /* translucent black scrim */).
- Dismiss: click the scrim, an `×` in the card corner, or press Escape — the card settles
  back onto the desk.
- Typography: a "typed card" look — a serif or typewriter-style stack (e.g.
  `"Courier New", Georgia, serif`), dark warm ink `rgb(51, 43, 33)` /* dark sepia */ on
  paper white, a ruled-line header like a real index card is a nice touch.
- Accessible: the expanded card is a `role="dialog"` with focus moved into it and returned
  on close.

### Card content structure

Each card has four sections:

1. Title line (demo name plus `CYD demo` kicker).
2. **What is this** — the description text below.
3. **Controls** — the how-to text below. Verify each claim against the running demo and
   the core source before shipping; adjust wording where behavior differs.
4. **Links** — one row of links: `Core code` (per-demo GitHub blob URL below),
   `Gallery` (`../../`), `GitHub repo` (`https://github.com/CarlKCarlK/linkage-blaze`),
   `Medium` (`https://medium.com/@carlmkadie`).

Every card ends with this shared line (small print):

> The simulation is the same `no_std`, no-allocation Rust that runs on a ~$15
> ESP32-2432S028R — the "Cheap Yellow Display" (CYD). Here the core is compiled to
> WebAssembly; on a real desk it drives a 320×240 touch panel.

### First-draft card text (edit freely for accuracy, keep the voice)

**Clock — What is this**

> An analog clock whose hands are a tiny linkage posed by the time of day, drawn with
> `embedded-graphics` over a WiFi-status and digital-time readout. It free-runs at the
> panel's native 320×240.

**Clock — Controls**

> It follows your local clock by default. Open the time setter (Feature 5) to scrub to any
> time of day; press **Live** to return to real time. The **boot** button restarts the
> device. *(Verify: the boot button is currently marked "intentionally inert" in
> `crates/linkage-blaze-clock-wasm/www/index.html` — if still inert, omit that sentence.)*

**Armatron — What is this**

> A robot arm with six joints, modeled as a linkage and driven by inverse kinematics. The
> solver steers the claw toward the red target dot on the grid; you can also pose every
> joint yourself.

**Armatron — Controls**

> Drag any yellow-dot slider: **raise hand**, **bend elbow**, **close hand**, **lower
> arm**, **spin whole arm**, **spin hand** pose the arm; **z zoom** and **x/y view** move
> the camera. Press **▶** to let the solver walk the claw to the target, **▶|** to
> single-step it. **prev / next** picks a different target. **cal** runs touch calibration
> (matters on real hardware). *(Verify each control against the running demo.)*

**Ballet — What is this**

> A motion-captured pirouette: a BVH recording converted into a linkage skeleton and
> replayed full screen. The top line shows the frame counter, frames per second, and the
> slow-motion factor.

**Ballet — Controls**

> It plays continuously on its own. *(Verify whether tapping the screen changes slow-motion
> or anything else — check `crates/linkage-blaze-example-core/src/ballet.rs` — and
> document what is actually interactive; if nothing is, say "Sit back and watch.")*

**Skeleton Clock — What is this**

> A clock told by a motion-captured figure: placards hanging from its hands show the hour
> and minute, and the figure shifts its pose as time passes.

**Skeleton Clock — Controls**

> It follows your local clock by default. Open the time setter to scrub to any time of day
> and watch the figure re-pose; press **Live** to return to real time.

## Feature 3: Scale-to-fit (fixes "too big on phones")

The desk scene must never overflow the viewport.

- Wrap the existing scene (`.simulator` or equivalent) in a scaler element. On load and
  resize, set `transform: scale(min(1, viewportWidth / sceneWidth, viewportHeight /
  sceneHeight))` with `transform-origin: center`. A few lines of JS with a resize listener
  (or `ResizeObserver`) is fine; a pure-CSS solution is also acceptable if it handles the
  Armatron stage's existing translate correctly.
- Scale the **wrapper only**. Do not touch the `.case` / `#screen` percentage geometry —
  those values are hand-calibrated to the case photo and must not drift.
- Keep `image-rendering: pixelated` crisp; uniform transform scaling is fine.
- Use `100dvh` (already present) so iOS Safari toolbars do not cause overflow.
- The back-to-gallery tag, index card (when expanded), and time setter are outside the
  scaled scene and lay themselves out against the real viewport.

## Feature 4: Device mode (fullscreen — "your phone is the ESP32")

A mode that shows only the live screen canvas, edge to edge.

- Entry: a small chip/button labeled `device mode` (or a screen-expand glyph) near the
  bottom-right of the page. Also hidden in device mode itself.
- On activation: request fullscreen on a dedicated container via the Fullscreen API. On
  iOS Safari (no element fullscreen), fall back to a `position: fixed; inset: 0` overlay
  at `100dvh`.
- In device mode: black background `rgb(0, 0, 0)` /* black */; hide the desk, case, cord,
  gallery tag, index card, and boot button; the canvas scales to the largest size that fits
  while preserving its aspect ratio (letterboxed), keeping `image-rendering: pixelated`.
  Touch input on the canvas must keep working (pointer coordinates already map through the
  canvas element, but verify after re-parenting/resizing — especially for Armatron's
  sliders).
- Exit: Escape / native fullscreen exit, plus a small translucent `×` chip in a corner for
  the CSS-fallback path. Listen to `fullscreenchange` so state stays consistent.
- Optional nicety: if the demo is landscape (Clock, Armatron) and the phone is portrait,
  show a brief "rotate your phone" hint that fades after a few seconds.

## Feature 5: Time-of-day setter redesign (Clock and Skeleton Clock only)

Today `buildTimeOfDaySlider` in `crates/linkage-blaze-clock-wasm/www/app.js` and
`crates/linkage-blaze-skeleton-clock-wasm/www/app.js` pins a 360 px-tall vertical slider
panel to the left edge; on phones it overlays the device. Replace it:

- **Collapsed state**: a small desk-styled chip (match the index-card paper look — a little
  brass-plaque or paper-tab reading a clock glyph plus the current state: `LIVE` or the
  overridden time, e.g. `3:45 PM`). Anchor it bottom-center or bottom-left of the
  viewport, outside the scaled scene, never covering the device screen at any viewport
  size.
- **Expanded state** (tap the chip): a horizontal scrubber docked along the bottom edge —
  full width up to a max of ~480 px, thumb-friendly height. Contents: time readout,
  `<input type="range">` (min 0, max 86400, step 60), a **Live** button, and a collapse
  control. Keep the exact WASM API: `set_time_of_day(seconds)` to override,
  `set_time_of_day(-1)` to resume live.
- Behavior carries over: start in live mode; dragging applies the override continuously;
  Live releases it and the readout returns to `LIVE`.
- **Device mode**: show a small translucent clock button in a corner that opens the same
  bottom scrubber, so time-scrubbing still works fullscreen.
- Implement once and use in both clock demos (see "Shared implementation" below). Clock
  and Skeleton Clock only; Armatron and Ballet must not load it.

## Shared implementation notes

- Features 1–5 are identical across the four demos. Write one canonical pair of files —
  `demo-ux.js` and `demo-ux.css` — parameterized by a small per-demo config object
  (title, description HTML, controls HTML, core-code URL, orientation, and a
  `buildTimeSetter` hook only for the two clocks). Because each `www/` is copied
  independently into frozen snapshots, duplicate the canonical files into all four `www/`
  directories, each with a header comment naming the master copy, plus
  `// TODO unify the four copies of demo-ux.js/css into one shared source`.
- Any CSS color written with numeric components needs a nearby approximate-color-name
  comment (repo convention).
- Do not remove or reword existing `TODO` comments anywhere.
- Do not disturb the calibrated `.case` / `#screen` / `.cord` percentage values or the
  `controls.js` calibration tuner and its `show_case_alignment_controls()` gate.
- Keep the existing service worker / manifest files (armatron) working; if new files are
  added to `www/`, check whether `sw.js` precaches a file list that needs updating.
- Follow this repo's markdown and code conventions in `AGENTS.md`.

## Rollout and verification

1. Implement everything in `crates/*/www` and `xtask/src/main.rs`.
2. For quick iteration on a single demo you may serve its `www/` directly after a
   `wasm-pack build <crate> --target web --out-dir www/pkg --out-name <out_name>` (names
   in `pages/demos.tsv`) — but note the back link `../../` will 404 in that setup; that is
   expected.
3. When the pages look right, freeze new versions:
   `just bump-demo-version clock && just bump-demo-version armatron && just bump-demo-version ballet && just bump-demo-version skeleton-clock`.
4. `just run-all-wasm`, then check at `http://localhost:8090/`:
   - Gallery shows the new header links; each card's "Open latest" goes to the new vN.
   - Every demo: gallery tag returns to the gallery; index card rests on the desk, expands
     to readable text with working links, and dismisses via scrim / `×` / Escape.
   - Desktop (~1400 px), tablet (~800 px), and phone (390×844 device-toolbar) viewports:
     no horizontal scroll, whole device visible, all controls tappable.
   - Device mode on each demo: canvas fills the viewport letterboxed and stays crisp;
     touch/drag works (Armatron sliders especially); exit works both via Escape and the
     `×` chip; gallery tag and card are hidden while active.
   - Clock and Skeleton Clock: time chip shows `LIVE`; expanding and scrubbing changes the
     rendered time immediately; **Live** resumes the real clock; the chip never overlaps
     the device screen on a phone; the scrubber is reachable inside device mode.
   - Old frozen versions (v1/v2) still load unchanged from the version selectors.
5. `just check-all` passes (xtask has tests; wasm builds run with `RUSTFLAGS="-D warnings"`).

## Non-goals

- No changes to embedded (ESP32) targets or the editor/printer/mocap pages.
- No retro-patching of existing frozen snapshots.
- No redesign of the demo simulations themselves.
